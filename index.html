约束

约束是对表结构数据的内容进行限制

目的：保障数据的完整性，正确，有效性

分类

约束 关键字 说明
非空约束 NOT NULL 字段值不能为 NULL
唯一约束 UNIQUE 该字段所有值唯一不重复（允许一个 NULL）
主键约束 PRIMARY KEY 一行唯一标识，非空 + 唯一，一张表只能一个主键
默认约束 DEFAULT 插入数据不指定该字段时，自动使用默认值
检查约束 CHECK 限制字段值满足自定义条件（MySQL 8.0.16 + 才真正生效）
外键约束 FOREIGN KEY 关联两张表，维护参照完整性、数据一致性

外键约束

具有外键的表称为子表，外键所关联的称为父表

外键的作用建立两个表之间的连接，确保数据的完整性

事务

事务的四大特性

•原子性（Atomicity）：事务是不可分割的最小操作单元，要么全部成功，要么全部失败。
•一致性(Consistency）：事务完成时，必须使所有的数据都保持一致状态。
•隔离性（Isolation）：数据库系统提供的隔离机制，保证事务在不受外部并发操作影响的独立环境下运行。
•持久性（Durability）：事务一旦提交或回滚，它对数据库中的数据的改变就是永久的。

并发事务的问题

问题现象 核心定义 导致原因（针对的操作） 通俗场景举例 如何解决（隔离级别）
🔴 脏读 (Dirty Read) 读到了其他事务未提交的数据。 另一个事务执行了 UPDATE/INSERT，但随后又回滚了。 老婆转账给你，你看到了入账短信（未提交），结果她撤销了转账，你空欢喜一场。 读已提交 (Read Committed) 及以上级别
🟠 不可重复读 (Unrepeatable Read) 同一事务内，先后两次读同一行，数据内容不一致。 另一个事务执行了 UPDATE/DELETE 并提交了。 你查余额有100元，此时老婆花掉50元，你再查变成了50元。两次单条查询结果变了。 可重复读 (Repeatable Read) 及以上级别 (MySQL默认)
🔴 幻读 (Phantom Read) 同一事务内，按相同条件查，两次查到的总行数（记录数）不一致。 另一个事务执行了 INSERT 并提交了。 你统计有10个VIP客户，期间新来了一个土豪开户，你再统计变成了11个。就像出现了“幻影”。 串行化 (Serializable) 或 InnoDB的间隙锁

事务的隔离级别

隔离级别 (Isolation Level) 脏读 不可重复读 幻读 特点与常见数据库
Read uncommitted (读未提交) ❌ 会发生 ❌ 会发生 ❌ 会发生 最低级别。什么限制都没有，基本没人用。
Read committed (读已提交) ✅ 已解决 ❌ 会发生 ❌ 会发生 Oracle / SQL Server / PostgreSQL 的默认级别。只能读已提交数据。
Repeatable Read (可重复读) ✅ 已解决 ✅ 已解决 ⚠️ 标准定义下会发生 (MySQL下基本解决) MySQL (InnoDB) 的默认级别。事务开启时生成快照，保证多次读取结果一致。
Serializable (串行化) ✅ 已解决 ✅ 已解决 ✅ 已解决 最高级别。所有事务排队执行，完全不并发，性能极差，极少使用。

题目练习

1.查询员工的姓名、年龄、职位、部门信息。

表 emp dept

连接条件emp.dept_id=dept.id

select e.name e.age e.job d.name from emp e inner join dept d on e.dept_id=d.id;

2.查询年龄小于30岁的员工姓名、年龄、职位、部门信息。

连接条件emp.dept_id=dept.id

select e.name e.age e.job.d.name from emp e inner join dept d on e.dept_id=d.id where emp.age<30;

3.查询拥有员工的部门ID、部门名称。

select distinct d.id d.name from dept d inner join emp e in emp.dept_id=dept.id

4.查询所有年龄大于40岁的员工，及其归属的部门名称;如果员工没有分配部门,也需要展示出来。

select e.*, d.name from emp e left join dept d on e.dept_id = d.id where e.age > 40 ;

案例

设计一张员工信息表，要求如下：

  1. 编号（纯数字）
  2. 员工工号(字符串类型，长度不超过10位)
  3. 员工姓名（字符串类型，长度不超过10位）
  4. 性别(男/女，存储一个汉字)
  5. 年龄（正常人年龄，不可能存储负数）
  6. 身份证号(二代身份证号均为18位，身份证中有X这样的字符）
  7. 入职时间(取值年月日即可)

create table emp(

ID int,

workno varchar(10) comment ‘编号’,

name varchar(10) comment ‘姓名’,

gender char(1) comment ‘性别’,

age tinyint unsigned comment ‘年龄’,

idcard char(18) comment ‘身份证号’,

entrydate date comment ‘入职时间’

)comment ‘员工表’;

测试的时候有好多错误

包括但是不限于

  1. verchar、werchar 应改为 VARCHAR
  2. tinint 应改为 TINYINT
  3. age unsigned tinint 应改为 age TINYINT UNSIGNED
  4. gender char(1) comment '性别'， 后面用了中文逗号 ，，应改成英文逗号 ,
  5. UNSIGNED 应放在数据类型后面，写作 TINYINT UNSIGNED
